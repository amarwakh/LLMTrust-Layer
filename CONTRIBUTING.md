# Contributing to LSEF

Contributions from security practitioners are actively welcomed. The framework improves when people who have done real security work on real LLM systems share what they have learned.

---

## What We Are Looking For

**High value contributions:**
- New threat categories or sub-categories based on real-world incidents or validated research
- Additional case studies (anonymised — no company names, no proprietary details, generalised lessons)
- Mitigation patterns that have been validated in production environments
- Corrections to existing content where the guidance is incorrect or outdated
- New evaluation checklists for system types not yet covered
- Updates to reflect new attack techniques as the threat landscape evolves

**Lower priority (but welcome):**
- Typo fixes and copy editing
- Formatting improvements
- Additional references and citations

---

## Contribution Standards

**Practitioner standard:** Content should reflect real security engineering experience, not theoretical possibilities. If you are contributing a mitigation pattern, it should be one that has been tested in a real system. If contributing a threat category, it should be based on observed or credibly documented attacks.

**No vendor promotion:** This framework is vendor-neutral. Do not contribute content that primarily exists to promote a specific security product or service.

**Cite your sources:** For threat categories and attack techniques, cite the original research where possible.

**Anonymise case studies:** Real-world examples are valuable. Never include company names, specific system names, or details that could identify an organisation. Generalise to the pattern.

---

## How to Contribute

1. Open an issue describing what you want to add or change — this ensures the contribution is aligned with the framework's direction before you invest time writing
2. Fork the repository
3. Make your changes in a branch
4. Submit a pull request with a clear description of what you changed and why
5. Be responsive to review feedback

---

## Code of Conduct

This project follows the [Contributor Covenant Code of Conduct](https://www.contributor-covenant.org/). Be direct, be substantive, be respectful.
